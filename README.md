# 今日から6日間の地上波/BSアニメ番組表

本日を起点に6日先までの地上波(関東)・BSアニメ番組表を表示する静的Webアプリ。作品にチェックを入れて「更新」ボタンを押すと、チェックした作品が上位に並び替わる。

公開URL: https://hinoyasai1984-afk.github.io/anime-timetable/

## 使い方

ビルド不要。`anime-timetable/`内で

```
python -m http.server 8000
```

を実行し、`http://localhost:8000`を開く。

## 仕組み

- データソース: [しょぼいカレンダー](https://cal.syoboi.jp/) の `json.php`（JSONP形式、CORS制限を受けない）
  - `Req=ProgramByDate` で放送予定を取得
  - `Req=TitleMedium` で作品名を取得
- 対象チャンネル: NHK総合/Eテレ、日本テレビ、TBS、フジテレビ、テレビ朝日、テレビ東京、TOKYO MX、tvk、チバテレビ、テレ玉、群馬テレビ、とちぎテレビ、および主要BS局（`app.js`の`WHITELIST_CH_IDS`にChIDを直書き）
- チェック状態は`localStorage`に保存（端末ローカル）
- `style.css`/`app.js`はキャッシュ対策のためバージョンクエリ（`?v=2`など）を付けて参照。更新時は忘れずに番号を上げる（詳細はルートの`CLAUDE.md`参照）

## 既知の制約（重要）

`ProgramByDate`は**現在時刻以降のデータしか返さない**（`Start`に過去日付を指定しても無視される、実機検証済み）。加えて、しょぼいカレンダーはボランティアによる手入力ベースの番組表のため、放送日が近づくまで登録されていないことが多い。

このため、本日から6日先までを問い合わせても、実際に表示されるのは**現時点で登録済みの分だけ**になる（例: 金曜に見ると土曜分までしか出ないことがある）。これはアプリのバグではなく、データソース側の登録タイミングに起因する仕様上の制約。

## 検討して見送った代替案（2026-07-24時点）

将来「本格対応」を検討する際の前提知識として記録。

1. **Annict GraphQL API**
   - `Program`型（チャンネル・放送時刻を持つ）自体は存在し、CORSも有効（`Access-Control-Allow-Origin: *`確認済み）。
   - ただし`Program`は`LibraryEntry`経由でのみ辿れる構造で、「全チャンネル横断で今週の放送を一括取得する」ような汎用クエリが存在しない。ユーザーが個々の作品を自分のライブラリに登録している前提のAPI設計のため、この用途には不向きと判断し見送り。

2. **moemoe.tokyo API**（`api.moemoe.tokyo`）
   - 昔よく使われていた無料・無認証の番組表APIだが、現在ドメインが名前解決不能（サービス終了と思われる）。

3. **しょぼいカレンダー db.php（`Command=ProgLookup`）**
   - `Range`パラメータ（`YYYYMMDD_HHMMSS-YYYYMMDD_HHMMSS`形式）で任意の過去日付範囲を指定でき、1リクエストで最大5,000件取得可能。**json.phpと違い過去データも取得できる。**
   - ただしCORS非対応（`Access-Control-Allow-Origin`ヘッダーなし、Originヘッダーを付けても付与されないことを実機確認済み）。ブラウザから直接は呼べない。

4. **CORSプロキシ経由でdb.phpを叩く**
   - `allorigins.win`等の公開プロキシで試したが、522エラー（接続不可）が発生し不安定。信頼性の面で本番採用は見送り。

5. **「前週の実績から次週の同曜日・同時間帯を推定する」ロジック**
   - ユーザー提案。過去実績自体は`Req=ProgramByCount`（TID・Countを指定）で取得可能なことを確認したが、**そもそも「今週まだ一度も番組表に登場していない作品のTID」を知る手段がない**ため、discoverできない作品には適用不可。
   - `ProgramByDate`はTIDを教えてくれる唯一の窓口だが、これも「現在時刻以降のみ」というdb.phpと同じ制約に縛られるため、過去週の全ラインナップを取得する用途には使えない。
   - 結論: 論理自体は妥当だが、「全作品一覧を取得する」という根本問題（＝#3のCORS制約）を解決しない限り実現不可能。

## 本格対応する場合の方針

上記の通り、この制約を解消するには**CORSを回避する中継（プロキシ）が必須**。

- Cloudflare Workers等の無料枠で動く軽量プロキシを1つ立て、そこ経由で`db.php`（`Command=ProgLookup`、`Range`パラメータ）を呼び出し、過去数週間分の放送実績から作品ごとの曜日・時間帯パターンを算出してJSONで返す、という構成が現実的。
- これにより「今週まだ登録されていない作品」も、直近数週間の実績があれば推定表示できるようになる見込み。
- ただし「静的サイトのみ」から「軽量バックエンドあり」への構成変更になるため、着手する際はCloudflareアカウントの要否から確認する。

現時点ではユーザー判断により見送り、現行の「登録済み分のみ表示」運用を継続中（2026-07-24）。
